# Poker Lab

一个逐步开发的德州扑克多人对战与 AI 策略训练平台，使用纯虚拟筹码。

项目希望结合两种体验：像坐在真实牌桌前一样打牌，以及在牌局结束后理解自己的决策。视觉与交互参考《荒野大镖客 2》的扑克体验，重点探索围桌视角、查看底牌、发牌、推出筹码和屏幕操作提示，并逐步形成自己的界面与场景。

**当前状态：项目规划与仓库初始化阶段。尚未建立 Maven 工程，也没有可运行的规则引擎或 3D 客户端。**

## 为什么做这个项目

以一个有明确规则、丰富边界和可视化结果的项目，系统学习 Java 后端、软件测试与工程实践。核心业务由开发者亲自实现，目标是能够独立解释代码、架构和设计取舍；AI 主要协助讲解、代码审查、工程配置与后续前端开发。

开发优先级是规则正确、行为可测试，再逐步完善联机能力与沉浸式体验。

## 目标体验

- 支持 2～6 人无限注德州扑克，逐步加入真人联机和简单 AI 对手。
- 提供三维牌桌、扑克牌、筹码和座位视角，逐步加入看牌、发牌、下注与收池动画。
- 使用清晰的操作提示展示合法动作、下注金额、底池和玩家状态。
- 保存牌局历史，支持复盘、策略对比与后续 AI 训练实验。

## 分阶段路线

### 1. 纯 Java 双人规则引擎

使用简单的单模块 Maven 工程，通过自动化测试验证完整的一手牌，按以下顺序推进：

1. 牌的表示、牌堆、洗牌与抽牌。
2. 五张牌的牌型比较，再扩展到七张选最佳五张。
3. 玩家、筹码、公共牌、行动顺序与牌局状态。
4. 下注动作校验与下注轮推进。
5. 弃牌获胜、摊牌、全押、平局与筹码结算。

双人规则需要覆盖庄家与盲注的行动顺序、最小加注、全押和未被跟注筹码退还。本阶段使用内存状态，不引入 Spring Boot、数据库或网页依赖。

### 2. 多人牌局与服务端接口

扩展至 2～6 人，处理多人行动顺序、边池与结算；按实际需要引入 Spring Boot API、WebSocket、MySQL 和牌局记录。

### 3. 浏览器 3D 牌桌与联机体验

拟使用 Three.js 展示场景，HTML/CSS 承载屏幕操作界面，Blender 制作模型。先用简单资源验证“一张牌桌、两张底牌、一个看牌动作”，再逐步加入完整交互、多人展示、音效和人物动画。

扑克牌共用牌体网格，通过不同牌面贴图表示 52 张牌。视觉原型可以独立探索，之后通过接口接入规则引擎。

### 4. 复盘与 AI 策略实验

先实现可解释的简单 AI，再利用牌局记录开展复盘、策略比较和训练实验，逐步明确分析指标与评估方式。

## 架构方向

Java 规则引擎负责牌局规则；联机阶段由服务端校验动作并决定状态和结算，客户端根据结果展示界面和播放动画。

规则逻辑与 Spring Boot、数据库和三维展示保持独立，便于自动化测试，也便于日后更换客户端技术。多人阶段按玩家权限下发可见信息，保留对手底牌等隐藏信息。

初期保持单模块，随实际需求演进架构。

## 开发与验证

- 当前使用 Java 21 和 Maven；工程建立后补充构建、测试与运行说明。
- 每个功能尽量经过：明确行为和边界 → 写验收案例 → 设计数据与接口 → 小步实现 → 测试验证 → 检查差异 → Git 提交。
- 测试关注牌不重复、牌型比较正确、非法动作不改变状态，以及结算前后筹码守恒。
- 随机测试保留可复现的种子；按阶段验证完整牌局，避免只验证孤立方法。
- 明确区分已经运行验证的行为与尚待验证的设计。
